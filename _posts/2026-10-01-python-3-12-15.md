## Python 3.12.15

**Release date:** October 1, 2026

## Security content in this release

* [gh-158446](https://github.com/python/cpython/issues/158446): Fix a crash or incorrect output that could occur when formatting a [`float`](https://docs.python.org/release/3.12.15/library/functions.html#float "float") or [`complex`](https://docs.python.org/release/3.12.15/library/functions.html#complex "complex") with a precision close to the platform’s `INT_MAX`.  [`PyOS_double_to_string()`](https://docs.python.org/release/3.12.15/c-api/conversion.html#c.PyOS_double_to_string "PyOS_double_to_string") now raises [`ValueError`](https://docs.python.org/release/3.12.15/library/exceptions.html#ValueError "ValueError") for any precision of that magnitude, regardless of presentation type or value, as the format string parsers already did for precisions above `INT_MAX`.
* [gh-156793](https://github.com/python/cpython/issues/156793): [`asyncio`](https://docs.python.org/release/3.12.15/library/asyncio.html#module-asyncio "asyncio: Asynchronous I/O."): [`loop.start_tls()`](https://docs.python.org/release/3.12.15/library/asyncio-eventloop.html#asyncio.loop.start_tls "asyncio.loop.start_tls") and [`loop.create_connection()`](https://docs.python.org/release/3.12.15/library/asyncio-eventloop.html#asyncio.loop.create_connection "asyncio.loop.create_connection") now validate the _server\_hostname_ argument if an [`ssl.SSLContext`](https://docs.python.org/release/3.12.15/library/ssl.html#ssl.SSLContext "ssl.SSLContext") is passed with _check\_hostname_ set to `True`, emitting [`DeprecationWarning`](https://docs.python.org/release/3.12.15/library/exceptions.html#DeprecationWarning "DeprecationWarning") if _server\_hostname_ is missing. (This will raise [`ValueError`](https://docs.python.org/release/3.12.15/library/exceptions.html#ValueError "ValueError") in Python 3.13 and later.)
* [gh-156793](https://github.com/python/cpython/issues/156793): [`ssl.SSLContext.wrap_bio()`](https://docs.python.org/release/3.12.15/library/ssl.html#ssl.SSLContext.wrap_bio "ssl.SSLContext.wrap_bio") now validates its _server\_side_, _server\_hostname_ and _session_arguments similar to [`ssl.SSLContext.wrap_socket()`](https://docs.python.org/release/3.12.15/library/ssl.html#ssl.SSLContext.wrap_socket "ssl.SSLContext.wrap_socket"), but for backward compatiblity reasons emits [`DeprecationWarning`](https://docs.python.org/release/3.12.15/library/exceptions.html#DeprecationWarning "DeprecationWarning") instead of [`ValueError`](https://docs.python.org/release/3.12.15/library/exceptions.html#ValueError "ValueError").

  In particular, a context with [`check_hostname`](https://docs.python.org/release/3.12.15/library/ssl.html#ssl.SSLContext.check_hostname "ssl.SSLContext.check_hostname") enabled and no _server\_hostname_ passed to `wrap_bio()`now emits [`DeprecationWarning`](https://docs.python.org/release/3.12.15/library/exceptions.html#DeprecationWarning "DeprecationWarning") to indicate the hostname wasn’t checked. (In Python 3.13 and later, this raises [`ValueError`](https://docs.python.org/release/3.12.15/library/exceptions.html#ValueError "ValueError").)
* [gh-157265](https://github.com/python/cpython/issues/157265): In [`tarfile`](https://docs.python.org/release/3.12.15/library/tarfile.html#module-tarfile "tarfile: Read and write tar-format archive files."), when extracting a link falls back to extracting a member of the archive, skip the member when the filter function returns None when called with the extracted member’s name replaced with the link’s.
* [gh-157190](https://github.com/python/cpython/issues/157190): Fixed a vulnerability in the [`tarfile`](https://docs.python.org/release/3.12.15/library/tarfile.html#module-tarfile "tarfile: Read and write tar-format archive files.") `data` and `tar` extraction filters where a crafted archive using a hard link to a symbolic link could change the permissions and modification time of a file outside the destination directory, and expose its contents inside the extracted tree. This addresses [**CVE 2026-82049**](https://www.cve.org/CVERecord?id=CVE-2026-82049).
* [gh-157953](https://github.com/python/cpython/issues/157953): Update bundled [libexpat](https://libexpat.github.io/) to version 2.8.5.
* [gh-156002](https://github.com/python/cpython/issues/156002): Bound the amount of data [`zipfile`](https://docs.python.org/release/3.12.15/library/zipfile.html#module-zipfile "zipfile: Read and write ZIP-format archive files.") decompresses per read for members compressed with bzip2, LZMA, or Zstandard, matching the existing limit for deflate. A small archive member could previously expand into an unbounded allocation even when read in small chunks.
* [gh-155999](https://github.com/python/cpython/issues/155999): Fix the [`tarfile`](https://docs.python.org/release/3.12.15/library/tarfile.html#module-tarfile "tarfile: Read and write tar-format archive files.") `tar` and `data` extraction filters creating directories outside the destination for members whose name leaves the destination and returns to it, such as `../evil/../dest/sub/file`. The containment check used the resolved path, but intermediate directories were created from the name as given.
* [gh-156293](https://github.com/python/cpython/issues/156293): Fix a crash in [`ssl`](https://docs.python.org/release/3.12.15/library/ssl.html#module-ssl "ssl: TLS/SSL wrapper for socket objects") when an [`sni_callback`](https://docs.python.org/release/3.12.15/library/ssl.html#ssl.SSLContext.sni_callback "ssl.SSLContext.sni_callback") switches a connection to another [`SSLContext`](https://docs.python.org/release/3.12.15/library/ssl.html#ssl.SSLContext "ssl.SSLContext")and the context that carries the callback is no longer referenced by the application. Servers that keep their `sni_callback` context alive (the usual case when it wraps the listening socket or is stored on the server object) were not affected. This addresses [**CVE 2026-19445**](https://www.cve.org/CVERecord?id=CVE-2026-19445).
* [gh-155292](https://github.com/python/cpython/issues/155292): Change the [`stringprep`](https://docs.python.org/release/3.12.15/library/stringprep.html#module-stringprep "stringprep: String preparation, as per RFC 3453") module and [`encodings.idna`](https://docs.python.org/release/3.12.15/library/codecs.html#module-encodings.idna "encodings.idna: Internationalized Domain Names implementation") codec to not consider Unicode codepoint attributes beyond those defined in [**RFC 3454**](https://datatracker.ietf.org/doc/html/rfc3454.html).
* [gh-155694](https://github.com/python/cpython/issues/155694): Fix [**CVE 2026-15806**](https://www.cve.org/CVERecord?id=CVE-2026-15806) by scoping [`HTTPPasswordMgr`](https://docs.python.org/release/3.12.15/library/urllib.request.html#urllib.request.HTTPPasswordMgr "urllib.request.HTTPPasswordMgr") credentials to the URL scheme, preventing credentials stored for an HTTPS URL from being used for a matching HTTP URL, while URIs without a scheme continue to match any scheme.
